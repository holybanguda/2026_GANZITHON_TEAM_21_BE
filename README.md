## 개인 개발 기록 — Backend Part 01

### 1. 개발 배경

본 브랜치(`backend_part01`)는 **EmOri 서비스의 API 명세서가 확정되기 전, 핵심 백엔드 기능을 선행 구현한 초기 개발 버전**입니다.

서비스 기획 내용을 바탕으로 주요 기능의 동작 가능성을 검토하고, 이후 팀원들과 API 명세 및 데이터 처리 방식을 구체화할 수 있도록 백엔드의 기본 구조와 비즈니스 로직을 구현했습니다.

이후 팀원들과의 논의를 통해 API 명세와 서비스 정책이 확정되었으며, 최종 팀 통합 코드는 `backend_part02` 브랜치에서 확인할 수 있습니다.

### 2. 초기 구현 주요 기능 및 기술적 특징

API 명세 확정 이전에 서비스의 핵심 기능을 선행 구현하고, 데이터 처리와 요청 상태 관리에 필요한 서버 로직을 구성했습니다.

- **사용자 인증 및 친구 관리:** 회원가입·로그인, 세션 관리, 친구 요청 및 관계 관리
- **감정 구슬 처리:** 생성·전송·수신·열람·반응 기능 및 `Idempotency-Key` 기반 중복 요청 처리
- **감정 기록:** 사용자별 감정 기록 조회 및 주간 단위 집계
- **음악 생성:** 음계 데이터를 활용한 WAV 멜로디 생성
- **푸시 알림:** Outbox와 스케줄러 기반 비동기 알림 처리
- **공통 서버 구조:** JDBC·트랜잭션 기반 데이터 처리 및 Controller·Service 계층 분리

각 기능의 구현 방식과 기술적 고려사항은 [개인 개발 기여 및 기술 분석](MY_CONTRIBUTIONS.md)에 정리했습니다.

### 3. 팀 통합본과의 관계

초기 구현 이후 팀원들과 API 명세 및 서비스 정책을 논의하면서 일부 기능의 책임과 데이터 구조가 변경되었습니다.

| 초기 구현 (Part 01) | 팀 통합본 (Part 02) | 주요 변화 |
|---|---|---|
| BeadService | OrbService, DispatchService, DeliveryService | 감정 구슬 관련 책임 분리 |
| RegisterService | AuthService | 인증 및 세션 관련 구조 재설계 |
| FriendService | FriendService | 친구 관계 API 및 데이터 모델 변경 |
| MusicService | SoundService, AsmrService | 음악 및 사운드 처리 구조 변경 |
| PushService | PushWorker 등 | 비동기 작업 처리 구조 확장 |

두 버전 사이에는 기능적 연관성이 존재하지만, 최종 통합본의 모든 코드가 초기 구현을 그대로 재사용한 것은 아닙니다.

본 브랜치는 **API 명세 확정 이전의 선행 구현 과정과 당시의 기술적 설계를 보존하기 위한 목적**으로 유지하고 있습니다.
